## 1.1 操作系统的目标和作用

### 1.1.1 OS 的四个目标

| 目标 | 含义 | 例子 |
| --- | --- | --- |
| <span style="color:#e03131">方便性</span> | 用户不用懂硬件，靠 OS 命令或图形界面就能操作计算机 | 双击图标就能打开程序，不用自己写机器指令 |
| <span style="color:#e03131">有效性</span> | 提高系统资源利用率，提高系统吞吐量 | CPU 等硬盘读数据时，先去跑别的程序 |
| <span style="color:#e03131">可扩充性</span> | 方便加入新功能、支持新硬件，和 OS 的结构紧密相关 | 插上新显卡，装个驱动就能用 |
| <span style="color:#e03131">开放性</span> | 遵循国际标准规范（如开放系统互连 OSI），不同厂商的软硬件能互相配合 | 按标准实现的网络协议，Windows 和 Linux 能互相通信 |

<span style="color:#e03131">方便性和有效性是 OS 最重要的两个目标。</span>

### 1.1.2 OS 的三个作用

**1. OS 是用户与计算机硬件系统之间的接口**

用户有三种方式使用 OS：

- **命令方式**：在命令行里敲命令，比如 PowerShell 里的 `dir`、Linux 里的 `ls`
- **系统调用方式**：程序员在程序里调用 OS 提供的 API，比如 Python 的 `open()` 最终会调用 OS 的“打开文件”系统调用
- **图形用户界面（GUI）方式**：用鼠标点窗口、图标、菜单，比如 Windows 桌面

**2. OS 是计算机系统资源的管理者**

计算机的资源分四类，OS 对应有四大管理：<span style="color:#e03131">处理机管理、存储器管理、I/O 设备管理、文件管理</span>。

举个例子：同时开着浏览器、微信和音乐播放器，谁先用 CPU、各自占多少内存、声音从哪个设备出来、下载的文件存到哪里，全是 OS 在安排。

**3. OS 实现了对计算机资源的抽象**

- <span style="color:#e03131">裸机</span>：完全没有软件的计算机。它只给用户提供硬件接口，用户必须非常了解物理接口是怎么实现的，所以很难用。
- **第一层抽象：I/O 设备管理软件。** 为了方便用户使用 I/O 设备，人们在裸机上覆盖一层 I/O 设备管理软件。它隐藏了 I/O 设备操作的具体细节，向上把 I/O 设备抽象成一组数据结构和一组 I/O 操作命令。用户只要用这些数据结构和命令就能输入输出数据，不用关心 I/O 具体是怎么实现的。
- <span style="color:#e03131">扩充机器（虚机器）</span>：覆盖了上述软件的机器。它向用户提供一个对硬件操作的抽象模型，用户通过这个模型的接口使用计算机，不需要了解物理接口的细节。<span style="color:#e03131">I/O 软件实现了对计算机硬件操作的第一个层次的抽象。</span>
- **继续往上叠：** 在第一层软件上再覆盖一层文件管理软件，它负责文件操作的细节，向上提供一组存取文件的数据结构和命令；文件管理之上再覆盖一层面向用户的窗口软件，用户就能在窗口环境下方便地使用计算机，形成一台功能更强的虚机器。

![OS 对计算机资源的多层抽象](/assets/img/os/os-layers.svg)
_图 1：从下往上依次是裸机、I/O 设备管理软件、文件管理软件、窗口软件。每覆盖一层软件，就得到一台功能更强的“扩充机器”。_

一句话总结：<span style="color:#e03131">OS 是铺设在计算机硬件上的多层软件的集合</span>，它不仅增强了系统的功能，还隐藏了对硬件操作的具体细节，实现了对计算机硬件操作的多个层次的抽象模型。<span style="color:#e03131">抽象层次越高，接口提供的功能越强，用户使用越方便。</span>

> 用写代码来类比：Python 里写 `open("a.txt").read()` 就能读文件，不用管文件存在硬盘的哪个扇区、磁头怎么移动。这些细节都被文件管理和 I/O 管理这两层软件藏起来了。
{: .prompt-info }

### 1.1.3 推动 OS 发展的主要动力

1. 不断提高计算机资源利用率（最早期、最主要的动力）
2. 方便用户
3. 器件的不断更新换代（比如 8 位 CPU 到 64 位 CPU，OS 也要跟着升级）
4. 计算机体系结构的不断发展（单处理机到多处理机，再到计算机网络）
5. 不断提出新的应用需求（比如多媒体、手机、物联网）

## 1.2 操作系统的发展过程

### 1.2.1 未配置操作系统的计算机系统

- **人工操作方式**：程序员把穿好孔的纸带或卡片装进机器，运行完再取走结果。缺点是用户独占全机，CPU 要等人工操作，<span style="color:#e03131">人机速度矛盾</span>非常严重。
- **脱机 I/O 方式**：先在一台外围机上把程序和数据输入到磁带，主机直接从高速的磁带读取；输出也是先写到磁带，再由外围机输出。这样减少了 CPU 的空闲时间，也提高了 I/O 速度。

### 1.2.2 单道批处理系统

- **处理过程**：把一批作业放在磁带上，由监督程序把作业一个接一个地调进内存运行。
- **优点**：作业连续处理，比人工操作提高了资源利用率和系统吞吐量。
- **缺点**：<span style="color:#e03131">内存中只有一道程序</span>，它做 I/O 的时候 CPU 只能干等，系统资源得不到充分利用。

### 1.2.3 多道批处理系统

- **多道程序设计**：在内存中同时存放多道作业，一道作业做 I/O 时，CPU 转去执行另一道作业。
- **优点**：<span style="color:#e03131">资源利用率高、系统吞吐量大</span>。
- **缺点**：<span style="color:#e03131">平均周转时间长、无交互能力</span>（作业交上去以后，用户就不能干预了）。

![单道和多道批处理对比](/assets/img/os/batch-single-vs-multi.svg)
_图 2：（a）单道时，程序 A 做 I/O 期间 CPU 空闲；（b）多道时，A 做 I/O 期间 CPU 转去运行 B、C，CPU 和 I/O 设备都忙起来了。_

> 生活里的例子：洗衣机在洗衣服时，你不会站在旁边干等，而是去煮饭、扫地。单道就是干等，多道就是同时安排几件事。
{: .prompt-info }

多道批处理系统需要解决的问题：处理机争用问题、内存分配和保护问题、I/O 设备分配问题、文件的组织和管理问题、作业管理问题、用户与系统的接口问题。后面的章节基本就是在逐个回答这些问题。

### 1.2.4 分时系统

- **为什么要引入**：用户需要<span style="color:#e03131">人机交互</span>（批处理做不到），还希望多个用户<span style="color:#e03131">共享主机</span>，而且每个人都感觉自己独占了主机。
- **定义**：在一台主机上连接多个带显示器和键盘的终端，同时允许多个用户共享主机资源，每个用户都能通过自己的终端以交互方式使用计算机。
- **关键问题**：让用户能和自己的作业交互，做到<span style="color:#e03131">及时接收、及时处理</span>。实现方法是作业直接进入内存，并采用<span style="color:#e03131">轮转运行方式</span>：给每个作业分一个很短的时间片，轮流使用 CPU。
- **四个特征**：
  - **多路性**：多台终端同时连到一台主机，分时使用
  - **独立性**：每个用户都感觉自己独占主机
  - **及时性**：用户请求能在很短时间内得到响应（1 到 3 秒）
  - **交互性**：用户可以通过终端和系统进行广泛的人机对话

### 1.2.5 实时系统

- **定义**：系统能及时响应外部事件的请求，在<span style="color:#e03131">规定的时间内</span>完成对事件的处理，并控制所有实时任务协调一致地运行。
- **最主要的特征**：<span style="color:#e03131">实时性</span>。
- **类型**：工业（武器）控制系统、信息查询系统、多媒体系统、嵌入式系统。
- **实时任务的分类**：
  - 按是否周期性执行：周期性实时任务、非周期性实时任务
  - 按对截止时间的要求：<span style="color:#e03131">硬实时任务</span>（必须在截止时间前完成，否则后果严重，比如汽车安全气囊、导弹控制）和<span style="color:#e03131">软实时任务</span>（偶尔超时可以接受，比如视频播放偶尔卡一帧）

实时系统和分时系统的比较：

| 特征 | 分时系统 | 实时系统 |
| --- | --- | --- |
| 多路性 | 有，多个终端用户 | 有，同时采集多路现场信息、控制多个对象 |
| 独立性 | 有 | 有 |
| 及时性 | 秒级，以人能接受的等待时间为准 | 更严格，由被控对象决定，可能是毫秒甚至微秒级 |
| 交互性 | 强，可以进行广泛的人机对话 | 弱，只能访问系统中特定的专用服务 |
| 可靠性 | 要求较高 | <span style="color:#e03131">要求更高</span>，出错可能造成严重后果 |

### 1.2.6 微机操作系统

| 类型 | 例子 |
| --- | --- |
| 单用户单任务 | CP/M、MS-DOS |
| 单用户多任务 | Windows 95/98 |
| 多用户多任务 | Solaris、Linux、Windows NT/Server |

### 1.2.7 嵌入式操作系统

- **嵌入式系统**：为完成某个特定功能而设计的软硬件结合体，通常有实时限制，比如响应速度、测量精度、持续时间。
- **嵌入式 OS**：用于嵌入式系统的 OS，比如 µC/OS-II、嵌入式 Linux、Windows Embedded、VxWorks、Android、iOS。
- **特点**：<span style="color:#e03131">系统内核小、系统精简、具有可配置性、高实时性</span>。

### 1.2.8 网络操作系统

- **概念**：在计算机网络环境下，对网络资源进行管理和控制，实现数据通信和网络资源共享，为用户提供网络资源接口的一组软件和规程的集合。例子有 UNIX、Linux、Windows NT/2000/Server。
- **特征**：硬件独立性、接口一致性、资源透明性、系统可靠性、执行并行性。
- **功能**：数据通信、应用互操作、网络管理。

### 1.2.9 分布式操作系统

- **分布式系统**：基于软件实现的一种多处理机系统，由多个处理机通过通信线路互连而成的<span style="color:#e03131">松耦合系统</span>。
- **分布式 OS**：配置在分布式系统上的公用 OS，例子有鸿蒙 OS。
- **特征**：<span style="color:#e03131">分布性、透明性、同一性、全局性</span>。
- **功能**：单处理机 OS 的主要功能，加上网络 OS 的全部功能，再加上通信管理、资源管理和进程管理功能。

> 网络 OS 和分布式 OS 的区别：在网络 OS 里，用户知道资源在哪台机器上（比如访问 `\\服务器\共享文件夹`）；在分布式 OS 里，整个系统对用户来说就像一台计算机，用户不需要知道任务具体在哪台机器上运行，这就是“透明性”。
{: .prompt-info }

## 1.3 操作系统的基本特征

<span style="color:#e03131">OS 的四个基本特征：并发、共享、虚拟、异步。其中并发和共享是多用户 OS 的两个最基本特征，二者互为存在条件。</span>

### 1.3.1 并发（Concurrence）

**1. 并行与并发**

- <span style="color:#e03131">并行</span>：两个或多个事件在<span style="color:#e03131">同一时刻</span>发生。
- <span style="color:#e03131">并发</span>：两个或多个事件在<span style="color:#e03131">同一时间间隔内</span>发生。

在多道程序环境下，并发是指一段时间内宏观上有多个程序在运行；但在单处理机系统中，每一时刻只能有一道程序执行，所以<span style="color:#e03131">微观上这些程序只能分时交替执行</span>。

![并行和并发对比](/assets/img/os/concurrency-vs-parallel.svg)
_图 3：上面两个 CPU 同时跑 A 和 B，这是并行；下面只有一个 CPU，A、B、C 轮流执行，这是并发。单处理机系统只能并发，不能并行。_

> 例子：一个人一边吃饭一边听歌，是并行；一个人吃一口饭、回一条消息、再吃一口饭，是并发。
{: .prompt-info }

**2. 引入进程**

在没有引入进程的 OS 里，同一个应用程序的计算程序和 I/O 程序只能顺序执行：计算程序执行告一段落后，才允许 I/O 程序执行。为计算程序和 I/O 程序分别建立一个进程后，这两个程序就能并发执行。如果为内存中的多个程序都分别建立一个进程，它们就都能并发执行，从而大大提高系统资源的利用率，增加系统吞吐量。

<span style="color:#e03131">进程</span>：在计算机系统中能独立运行、并作为资源分配的基本单位。它由一组机器指令、数据和堆栈等组成，是一个能独立运行的活动实体。<span style="color:#e03131">进程和并发是 OS 运行的基础。</span>

> 动手看看：在 Windows 里按 `Ctrl+Shift+Esc` 打开任务管理器，“进程”页里的每一行就是一个进程。在 Python 里运行 `import os; print(os.getpid())`，打印的就是当前这个 Python 进程的编号。
{: .prompt-tip }

### 1.3.2 共享（Sharing）

OS 环境下的资源共享，也叫资源复用，是指系统中的资源可以供内存中多个并发执行的进程共同使用。

1. <span style="color:#e03131">互斥共享方式</span>：规定一段时间内只允许一个进程访问该资源。这种一次只能给一个进程用的资源叫<span style="color:#e03131">临界资源</span>，比如打印机：两个文档同时打印，纸上的内容就会混在一起。
2. <span style="color:#e03131">同时访问方式</span>：一段时间内允许多个进程同时访问资源。这里的“同时”在单处理机上是宏观的，微观上仍是交替访问，比如多个程序轮流读写同一块硬盘。

### 1.3.3 虚拟（Virtual）

用来实现虚拟的技术最早出现在通信系统中。在 OS 中，<span style="color:#e03131">通过某种技术把一个物理实体变成若干个逻辑上的对应物，称为虚拟</span>。

1. <span style="color:#e03131">时分复用技术</span>：利用资源的空闲时间为其他用户服务。比如虚拟处理机：一个 CPU 通过分时轮流运行多个进程，每个进程都觉得自己有一个 CPU。虚拟设备也是这个原理。
2. <span style="color:#e03131">空分复用技术</span>：利用存储器的空闲空间存放和运行其他程序。比如虚拟存储：电脑只有 8 GB 内存，却能同时开很多占内存的程序，因为 OS 会把暂时不用的部分放到硬盘上，让每个程序都觉得自己有很大的内存。

### 1.3.4 异步（Asynchronism）

在多道程序环境下，系统允许多个进程并发执行。在单处理机系统中只有一个处理机，每次只能执行一个进程，其余进程只能等待。由于资源等因素的限制，进程通常不可能一气呵成地执行完，而是<span style="color:#e03131">走走停停</span>。

所以可能出现先进入内存的作业后完成、后进入内存的作业先完成的情况。<span style="color:#e03131">进程以人们不可预知的速度向前推进，这就是进程的异步性。</span>

> 不过只要运行环境相同，作业经过多次运行都会得到完全相同的结果。异步性影响的是执行快慢，不影响结果。
{: .prompt-warning }

## 1.4 操作系统的运行环境

### 1.4.1 硬件支持

OS 要跑起来，首先得被找到并装进内存：

1. 开机后，位于<span style="color:#e03131">固件</span>（比如 BIOS 或 UEFI）中的引导程序开始执行
2. 引导程序<span style="color:#e03131">定位 OS 内核，并把它加载到内存</span>
3. 之后，OS 等待事件发生。事件由硬件中断或软件中断引起
4. 程序平时存放在外存（硬盘），执行时位于内存，其中的指令由 CPU 执行

### 1.4.2 操作系统内核

内核<span style="color:#e03131">常驻内存</span>，通常与硬件紧密相关。不同类型和规模的 OS，内核包含的功能有一些差异，但大多数都包含以下两类功能：

1. **支撑功能**
   - 中断处理：内核最基本的功能，各种操作都离不开中断
   - 时钟管理：比如分时系统里的时间片，就是靠时钟管理来控制的
   - <span style="color:#e03131">原语操作</span>：由若干条指令组成、用来完成一定功能的过程。它是<span style="color:#e03131">原子操作</span>，要么全做，要么全不做，不可分割
2. **资源管理功能**
   - 进程管理
   - 存储器管理
   - 设备管理

> 原子操作的例子：银行转账要“A 账户减 100”和“B 账户加 100”两步一起完成。如果只做了第一步就中断，钱就凭空消失了。这和数据库里的事务是同一个思想。
{: .prompt-info }

### 1.4.3 处理机的双重工作模式

处理机至少需要两种单独的运行模式：

| 模式 | 别名 | 能执行的指令 |
| --- | --- | --- |
| <span style="color:#e03131">内核态</span> | 管态、系统态 | 包括特权指令在内的一切指令 |
| <span style="color:#e03131">用户态</span> | 目态 | 不能执行特权指令 |

- <span style="color:#e03131">特权指令</span>：在内核态下运行的指令，如果误用可能引起系统崩溃。它不仅能访问用户空间，还能访问系统空间，比如启动外部设备、设置系统时钟、关中断、切换执行状态、I/O 指令。
- <span style="color:#e03131">非特权指令</span>：在用户态下运行的指令。应用程序使用的都是非特权指令，只能访问用户空间，这样可以防止应用程序的运行异常对系统造成破坏。

硬件提供一个<span style="color:#e03131">模式位（mode bit）</span>来区分系统正在运行的是用户代码还是内核代码：<span style="color:#e03131">内核态为 0，用户态为 1</span>。当中断、异常或系统调用发生时，硬件自动切换到内核态；处理完后再设置回用户态，并把结果返回给用户程序。

![用户态到内核态的切换](/assets/img/os/mode-switch.svg)
_图 4：用户程序在用户态（模式位为 1）运行，调用系统调用时陷入（trap）内核，模式位变成 0，内核执行系统调用；执行完后模式位设回 1，返回用户程序继续运行。_

> 例子：你的 Python 程序想读文件，但它在用户态，不能直接执行操作硬盘的 I/O 指令。它只能发起系统调用，切到内核态，由 OS 代为读取，再把数据交回来。这就像去银行取钱，你不能自己进金库，只能找柜员办。
{: .prompt-info }

### 1.4.4 中断与异常

<span style="color:#e03131">OS 是中断驱动的</span>：它总在等待某个事件发生，而事件总是由中断或异常引起的。

| 类型 | 来源 | 例子 |
| --- | --- | --- |
| <span style="color:#e03131">中断（interrupt）</span> | 硬件引起 | 按下键盘、移动鼠标、硬盘读完数据、时钟到点 |
| <span style="color:#e03131">异常/陷阱（trap）</span> | 软件引起 | 出错：除数为零、无效的存储访问；用户程序的特定请求：执行 OS 的某个服务（系统调用） |

## 1.5 操作系统的主要功能

### 1.5.1 处理机管理功能

1. **进程控制**：创建进程、撤销（终止）进程、控制进程的状态转换
2. **进程同步**：协调多个进程的运行顺序，常用<span style="color:#e03131">信号量机制</span>
3. **进程通信**：进程之间交换信息，分为直接通信和间接通信
4. **调度**：分为<span style="color:#e03131">作业调度</span>（从外存挑作业放进内存）和<span style="color:#e03131">进程调度</span>（从内存里挑进程分配 CPU）

### 1.5.2 存储器管理功能

1. **内存分配和回收**：给程序分配内存，程序结束后收回
2. <span style="color:#e03131">内存保护</span>：确保每个用户程序只在自己的内存空间里运行，绝不允许用户程序访问 OS 的程序和数据
3. <span style="color:#e03131">地址映射</span>：把程序中的逻辑地址转换成内存中的物理地址
4. <span style="color:#e03131">内存扩充</span>：借助虚拟存储技术，从逻辑上扩充内存容量，需要请求调入功能和置换功能

### 1.5.3 设备管理功能

主要任务：完成用户进程提出的 I/O 请求；提高 CPU 和 I/O 设备的利用率。

1. **缓冲管理**：用缓冲区机制缓和 CPU 和 I/O 设备速度不匹配的矛盾
2. **设备分配**：根据用户的 I/O 请求分配所需设备
3. **设备处理**：由设备驱动程序实现 CPU 和设备控制器之间的通信

### 1.5.4 文件管理功能

1. **文件存储空间的管理**：为文件分配和回收外存空间
2. **目录管理**：为每个文件建立目录项，实现<span style="color:#e03131">按名存取</span>，用户只要给出文件名就能访问文件
3. **文件的读/写管理和保护**：控制文件读写，防止文件被未授权的用户访问或破坏

### 1.5.5 操作系统与用户之间的接口

1. **用户接口**
   - <span style="color:#e03131">联机用户接口</span>：命令行方式（CLI），比如 PowerShell、Linux 终端
   - <span style="color:#e03131">脱机用户接口</span>：用于批处理系统，用户事先写好作业说明书（作业控制语言 JCL），交给系统按说明执行
   - <span style="color:#e03131">图形用户接口</span>（GUI）：窗口、图标、菜单
2. <span style="color:#e03131">程序接口</span>：由一组<span style="color:#e03131">系统调用</span>组成，每个系统调用都是一个能完成特定功能的子程序。程序员写代码时用的就是它

### 1.5.6 现代操作系统的新功能

1. **保障系统安全**：认证技术、密码技术、访问控制技术、反病毒技术
2. **支持用户通过联网获取服务**：网络通信、资源管理、应用互操作
3. **可处理多媒体信息**：接纳控制技术、实时调度、多媒体文件的存储

## 1.6 操作系统的结构设计

### 1.6.1 简单结构

也叫<span style="color:#e03131">整体系统结构</span>。OS 没有清晰的结构，是为数众多的一组过程的集合，内部复杂、混乱。例子有 MS-DOS、早期的 UNIX。

### 1.6.2 模块化结构

- 把 OS 按功能划分成若干个模块，并规定好模块之间的接口，称为<span style="color:#e03131">“模块-接口法”</span>。
- **优点**：提高 OS 设计的正确性、可理解性和易维护性；增强 OS 的可适应性；加速 OS 的开发过程。
- 大部分现代 OS 采用<span style="color:#e03131">可加载的内核模块</span>：内核有一组核心组件提供核心服务，其他服务可以在内核运行时动态加载，每个组件在需要时才被加载进内核。例子有 Linux、Mac OS X、Solaris 和 Windows。

> 例子：Windows 插上一个新 U 盘或新打印机，系统会自动加载对应的驱动模块，不需要重装系统。
{: .prompt-info }

### 1.6.3 分层式结构

- 把 OS 划分成若干层，在低层之上构建高层。<span style="color:#e03131">底层（第 0 层）是硬件，最高层（第 N 层）是用户接口。每一层只依赖紧邻它的下一层。</span>
- **优点**：容易保证系统的正确性；易维护、易扩充。
- **缺点**：<span style="color:#e03131">系统效率低</span>，因为一个请求要一层一层往下传。
- 例子：THE、Multics。

![分层式结构](/assets/img/os/layered-os.svg)
_图 5：从第 0 层的硬件往上一层层构建，直到第 N 层的用户接口。每层只调用紧邻它的下一层。_

> 和写代码的类比：Web 项目常分成 Controller、Service、DAO 三层，Controller 只调 Service，Service 只调 DAO，结构清楚好维护，但每个请求都要穿过好几层。
{: .prompt-info }

### 1.6.4 微内核结构

- **基本概念**：
  - <span style="color:#e03131">足够小的内核</span>：只保留最基本的功能，即进程管理、低级存储器管理、中断和陷入处理
  - <span style="color:#e03131">基于客户/服务器模式</span>：文件服务、设备服务等大部分功能做成运行在用户态的服务器进程
  - 应用“<span style="color:#e03131">机制与策略分离</span>”原理：内核只提供“怎么做”的机制，“做什么”的策略交给服务器
  - 采用面向对象技术
- **优点**：提高了系统的可扩展性；增强了系统的可靠性；可移植性强；支持分布式系统；融入了面向对象技术。
- **问题**：<span style="color:#e03131">运行效率有所降低</span>。原因是完成一次客户的服务请求，需要通过消息进行多次交互，还要在用户态和内核态之间多次切换上下文。
- 实例：Mach OS、Windows 2000/XP。

![微内核结构](/assets/img/os/microkernel.svg)
_图 6：客户进程和各种服务器（进程、I/O 设备、文件、存储器服务器）都运行在用户态，彼此不直接调用。客户发出的请求先交给微内核，再由微内核转发给对应的服务器。_

### 1.6.5 外核结构

- **基本思想**：内核不提供传统 OS 中进程、虚拟存储器之类的抽象，而是<span style="color:#e03131">专注于物理资源的隔离（保护）与复用</span>。
- 内核非常小，只负责保护系统资源；硬件资源由应用程序自己管理。
- 实例：Aegis 系统。

## 1.7 系统调用

### 1.7.1 系统调用的基本概念

- **概念**：<span style="color:#e03131">应用程序请求 OS 内核完成某项功能时的一种过程调用</span>，是用户和内核之间的接口。
- **目的**：让应用程序通过它间接调用 OS 内核中的相关过程，获得相应的服务。
- **与一般过程调用的区别**（重点）：
  1. <span style="color:#e03131">运行在不同的系统状态</span>：一般过程的调用者和被调用者都在用户态；系统调用的调用者在用户态，被调用者在内核态
  2. <span style="color:#e03131">状态的转换</span>：系统调用要通过软中断（陷入）从用户态切换到内核态，一般过程调用不需要
  3. <span style="color:#e03131">返回问题</span>：一般过程调用完会直接返回调用它的程序；系统调用返回前，OS 可能会重新调度，让更紧急的进程先运行
  4. <span style="color:#e03131">嵌套调用</span>：系统调用也能嵌套，但嵌套层数有限制，而一般过程对嵌套层数没有限制

> 用 Python 体会一下：下面这几行每一行背后都有系统调用。
{: .prompt-tip }

```python
import os

pid = os.getpid()          # 信息维护类：获取当前进程号
f = open("demo.txt", "w")  # 文件操纵类：创建并打开文件
f.write("hello OS\n")      # 文件操纵类：写文件
f.close()                  # 文件操纵类：关闭文件
print(pid)                 # 往屏幕输出，最终也是一次写设备的系统调用
```

`open`、`write` 都是 Python 提供的普通函数，它们内部会去调用 Windows 或 Linux 提供的系统调用，真正碰硬盘的是内核。

### 1.7.2 系统调用的类型

| 类型 | 作用 |
| --- | --- |
| <span style="color:#e03131">进程控制类</span> | 创建和终止进程、获得和设置进程属性、等待某事件出现 |
| <span style="color:#e03131">文件操纵类</span> | 创建和删除文件、打开和关闭文件、读写文件 |
| <span style="color:#e03131">进程通信类</span> | 用于进程之间通信 |
| <span style="color:#e03131">设备管理类</span> | 申请和释放设备、设备 I/O 重定向、获得和设置设备属性 |
| <span style="color:#e03131">信息维护类</span> | 获取系统和文件的时间信息、OS 版本、当前用户、空闲内存、磁盘等信息 |
