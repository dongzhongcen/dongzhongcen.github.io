## 2.1 前趋图和程序执行

### 2.1.1 前趋图

<span style="color:#e03131">前趋图（Precedence Graph）是一个有向无循环图（DAG）</span>，用来描述进程（或程序段）之间执行的先后顺序。

- **结点**：表示一个进程或一个程序段，甚至一条语句
- **有向边**：表示前趋关系。\(P_i \rightarrow P_j\) 表示 \(P_i\) 必须在 \(P_j\) 开始之前完成，\(P_i\) 是 \(P_j\) 的直接前趋，\(P_j\) 是 \(P_i\) 的直接后继
- 没有前趋的结点叫**初始结点**，没有后继的结点叫**终止结点**
- <span style="color:#e03131">前趋图中不能有循环</span>，否则会出现“A 等 B、B 又等 A”这种不可能满足的顺序

![前趋图：顺序执行与并发执行](/assets/img/os/ch2-precedence.svg)

**图解：** 图里 I 是输入、C 是计算、P 是打印。

- **（a）顺序执行**：一条直线，I1 → C1 → P1 → I2 → C2 → P2。第二个程序的输入 I2 必须等第一个程序打印完 P1 才能开始。
- **（b）并发执行**：每个作业仍然要先输入、再计算、再打印（竖着的斜箭头 \(I_i \rightarrow C_i \rightarrow P_i\)），同一类操作也要排队（横箭头 \(I_i \rightarrow I_{i+1}\)）。但 I2 只要求 I1 做完，不用等 P1，所以 I2、C1 可以同时进行，I3、C2、P1 也可以同时进行。前趋关系就是 \(I_i \rightarrow C_i,\ I_i \rightarrow I_{i+1},\ C_i \rightarrow P_i,\ C_i \rightarrow C_{i+1},\ P_i \rightarrow P_{i+1}\)。
- **（c）语句级例子**：S3 要用 S1 算出的 a 和 S2 算出的 b，所以有 S1 → S3、S2 → S3；S4 要用 c，所以有 S3 → S4。<span style="color:#e03131">S1 和 S2 之间没有箭头，说明它们可以并发执行</span>。

### 2.1.2 程序顺序执行

一个较大的程序通常由若干个程序段组成，执行时必须按某种先后次序逐个执行，前一个操作完成后才能执行后继操作。

顺序执行有三个特征：

| 特征 | 含义 |
| --- | --- |
| <span style="color:#e03131">顺序性</span> | 处理机严格按照程序规定的顺序执行，每个操作必须在下一个操作开始前结束 |
| <span style="color:#e03131">封闭性</span> | 程序运行时独占全机资源，结果只取决于程序本身，不受外界影响 |
| <span style="color:#e03131">可再现性</span> | 只要初始条件和执行环境相同，重复执行得到的结果一定相同 |

### 2.1.3 程序并发执行

采用多道程序技术，把多个程序同时装入内存，让它们并发运行。只有**不存在前趋关系**的程序之间才可能并发执行。

并发执行带来了三个新特征：

| 特征 | 含义 |
| --- | --- |
| <span style="color:#e03131">间断性</span> | 并发程序之间互相制约，程序会“执行 → 暂停执行 → 执行”走走停停 |
| <span style="color:#e03131">失去封闭性</span> | 多个程序共享全机资源，一个程序的执行状态会受其他程序影响 |
| <span style="color:#e03131">不可再现性</span> | 即使环境和初始条件都相同，多次执行的结果也可能不同 |

**不可再现性的例子：** 程序 A 和程序 B 共享变量 N，以不同速度循环运行，某时刻 N 的值为 n。

```text
程序 A：  N := N + 1;
程序 B：  print(N);  N := 0;
```

| A 的 `N := N + 1` 执行的时机 | 打印出的值 | 最后 N 的值 |
| --- | --- | --- |
| 在 `print(N)` 和 `N := 0` 之前 | n + 1 | 0 |
| 在 `print(N)` 和 `N := 0` 之后 | n | 1 |
| 在 `print(N)` 和 `N := 0` 之间 | n | 0 |

同样的两段程序，只因为执行快慢不同，结果就不同了，这就是<span style="color:#e03131">失去了可再现性</span>。为了让并发执行的程序结果可再现，OS 引入了“进程”这个概念来描述和控制并发。

## 2.2 进程的描述

### 2.2.1 进程的定义与特征

**进程实体**由三部分组成：<span style="color:#e03131">程序段 + 相关的数据段 + PCB</span>。平时说的“创建进程”，实际上是创建进程实体中的 PCB；“撤销进程”实际上是撤销 PCB。

几种典型定义：

1. 进程是程序的一次执行。
2. 进程是一个程序及其数据在处理机上顺序执行时所发生的活动。
3. 进程是程序在一个数据集合上运行的过程，它是系统进行资源分配和调度的一个独立单位。

教材给出的定义：<span style="color:#e03131">进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。</span>

在 Linux 里用 `ps -ef` 或 `top`，在 Windows 里打开任务管理器，看到的每一行就是一个进程。

**进程的四个特征：**

| 特征 | 含义 |
| --- | --- |
| <span style="color:#e03131">动态性（最基本的特征）</span> | 进程是程序的一次执行，有生命周期：因创建而产生，因调度而执行，因终止而消亡 |
| 并发性 | 多个进程实体同存于内存中，能在一段时间内同时运行 |
| 独立性 | 进程实体是一个能独立运行、独立获得资源和独立接受调度的基本单位 |
| 异步性 | 进程按各自独立的、不可预知的速度向前推进 |

**进程和程序的区别：**

| 进程 | 程序 |
| --- | --- |
| <span style="color:#e03131">动态的</span>，是程序的一次执行 | <span style="color:#e03131">静态的</span>，是存放在外存里的指令集合 |
| 有生命周期，暂时存在 | 可以长期保存 |
| 在内存中 | 在外存中 |
| 进程是程序的一个实例 | 程序是进程的代码部分 |

一个程序可以对应多个进程，比如同时打开两个记事本窗口，就是同一个程序产生了两个进程。

### 2.2.2 进程的基本状态与转换

**三种基本状态：**

- <span style="color:#e03131">就绪状态（Ready）</span>：进程已分配到除 CPU 以外的所有必要资源，只要再获得 CPU 就能立即执行。系统中通常有多个就绪进程，排成一个**就绪队列**。
- <span style="color:#e03131">执行状态（Running）</span>：进程已获得 CPU，程序正在执行。单处理机系统中同一时刻只有一个进程处于执行状态；多处理机系统中可以有多个。
- <span style="color:#e03131">阻塞状态（Block）</span>：正在执行的进程因为发生某事件（如请求 I/O、申请缓冲区失败）暂时无法继续执行，此时即使把 CPU 给它也没用。根据阻塞原因不同，系统会设置多个**阻塞队列**。

![进程的三种基本状态及转换](/assets/img/os/ch2-three-state.svg)

**图解：** 三个椭圆是三种状态，箭头是状态之间能发生的转换，箭头上的字是触发转换的原因。

- **就绪 → 执行**（蓝色）：进程调度程序选中了它，把 CPU 分给它。
- **执行 → 就绪**（橙色）：分给它的时间片用完了（或被更高优先级的进程抢占），它还能运行，只是暂时让出 CPU。
- **执行 → 阻塞**（红色）：进程自己发起了 I/O 请求或在等某个事件，没法继续运行。
- **阻塞 → 就绪**（绿色）：I/O 完成或等待的事件发生了。注意它回到的是就绪而不是执行，还要重新排队等 CPU。

<span style="color:#e03131">图里没有“就绪 → 阻塞”和“阻塞 → 执行”这两条箭头</span>：就绪进程没在运行，不可能自己发起 I/O 请求；阻塞进程被唤醒后必须先进就绪队列，再由调度程序选中才能执行。

**创建状态和终止状态：**

- <span style="color:#e03131">创建状态</span>：进程正在被创建，还不能被调度。创建过程是：申请空白 PCB → 向 PCB 填写控制和管理信息 → 分配运行所需资源 → 把状态改成就绪，插入就绪队列。如果资源不够（比如内存不足），进程就停在创建状态。
- <span style="color:#e03131">终止状态</span>：进程运行结束或被终止后，先等 OS 做善后处理，然后把 PCB 清零、归还给系统。

这样就有了五种状态：创建、就绪、执行、阻塞、终止。

### 2.2.3 挂起操作和进程状态的转换

**挂起**就是把进程暂时“冻结”：被挂起的进程不能参与调度，通常还会被换出到外存。与挂起相对的操作叫**激活**。

引入挂起的原因：

1. 终端用户的需要：用户发现程序有问题，想暂停下来检查
2. 父进程的请求：父进程想考查或修改子进程
3. 负荷调节的需要：系统负荷太重时，挂起一些不重要的进程，保证系统正常运行
4. OS 的需要：OS 想挂起某些进程，检查运行中的资源使用情况或做记账

引入挂起后，就绪和阻塞各分成两种：<span style="color:#e03131">活动就绪（Readya）、静止就绪（Readys）、活动阻塞（Blockeda）、静止阻塞（Blockeds）</span>。加上创建、执行、终止，一共七种状态，这就是 PPT 里的“七状态进程模型”。

![引入创建、终止和挂起后的进程状态转换](/assets/img/os/ch2-seven-state.svg)

**图解：** 蓝色椭圆是“活动”状态（进程在内存里），黄色椭圆是“静止”状态（进程被挂起，一般换到了外存）。

- **创建 → 活动就绪**：OS 许可，内存也够，直接进入活动就绪。
- **创建 → 静止就绪**：OS 许可，但内存不够，只能先放在外存，处于静止就绪。
- **活动就绪 ⇄ 执行**：调度和时间片完，和三状态图一样。
- **执行 → 活动阻塞**：请求 I/O；**活动阻塞 → 活动就绪**：事件发生。
- **左右两列的竖向箭头**：<span style="color:#e03131">挂起</span>（红色，向下）让进程从活动变成静止，<span style="color:#e03131">激活</span>（蓝色，向上）让它从静止回到活动。就绪和阻塞两列各有一对。
- **静止阻塞 → 静止就绪**：被挂起的阻塞进程等的事件发生了，它变成就绪，但仍然是挂起的，要激活后才能被调度。
- **执行 → 静止就绪**（灰色虚线）：正在执行的进程被挂起，直接变成静止就绪。
- **执行 → 终止**：进程运行完或被终止，释放资源。

### 2.2.4 进程管理中的数据结构

OS 为每个资源和每个进程都设置了数据结构，大致分四类：<span style="color:#e03131">内存表、设备表、文件表、进程表</span>。进程表就是由 PCB 组成的。

**进程控制块 PCB（Process Control Block）**

<span style="color:#e03131">PCB 是 OS 中最重要的记录型数据结构，是进程存在的唯一标志，常驻内存。</span>OS 就是根据 PCB 来感知和控制进程的。

PCB 的作用：

1. 作为独立运行基本单位的标志：有 PCB 才算一个能并发运行的进程
2. 能实现间断性运行方式：进程暂停时把 CPU 现场保存在 PCB 里，下次从这里恢复
3. 提供进程管理所需要的信息：程序和数据在内存或外存的地址都记在 PCB 里
4. 提供进程调度所需要的信息：状态、优先级、已等待时间等
5. 实现与其他进程的同步与通信：PCB 里有信号量、消息队列指针等

PCB 中的信息：

| 类别 | 主要内容 |
| --- | --- |
| <span style="color:#e03131">进程标识符</span> | 外部标识符（给用户用的名字）、内部标识符（OS 用的 PID）、父进程和子进程标识符 |
| <span style="color:#e03131">处理机状态</span> | 通用寄存器、指令计数器（PC）、程序状态字（PSW）、用户栈指针，也就是“CPU 现场” |
| <span style="color:#e03131">进程调度信息</span> | 进程状态、优先级、调度所需的其他信息（如已等待时间）、事件（阻塞原因） |
| <span style="color:#e03131">进程控制信息</span> | 程序和数据的地址、进程同步和通信机制、资源清单、链接指针 |

**PCB 的组织方式有三种：**

1. **线性方式**：把所有 PCB 放在一张线性表里，表的首址存在内存的专用区域。实现简单、开销小，但每次查找都要扫描整张表，适合进程数不多的系统。
2. **链接方式**：把同一状态的 PCB 用链接字串成队列，形成就绪队列、阻塞队列、空闲队列等。
3. **索引方式**：按进程状态建立索引表（就绪索引表、阻塞索引表等），表项里记录对应 PCB 在 PCB 表中的地址。

![PCB 的组织方式：链接方式与索引方式](/assets/img/os/ch2-pcb-org.svg)

**图解：**

- **（a）链接方式**：左边四个深色框是 OS 保存的队首指针。执行指针指向正在运行的 PCB 3；就绪队列指针指向 PCB 1，PCB 1 的链接字再指向 PCB 5，依次串下去，最后的 ∧ 表示队列结束。阻塞队列和空闲队列同理。
- **（b）索引方式**：右边是存放所有 PCB 的 PCB 表。就绪表指针指向“就绪索引表”，表里每一项存的是一个就绪进程的 PCB 地址，箭头指向 PCB 表里对应的那一行；阻塞索引表也一样。要找所有就绪进程时只需要查索引表，不用扫描整张 PCB 表。

**进程队列：** 就绪队列中的进程被调度后上 CPU 执行，时间片到了（Timeout）就回到就绪队列尾部；如果执行中等待事件 n，就进入等待事件 n 的阻塞队列；事件 n 发生后，<span style="color:#e03131">对应阻塞队列中的进程移到就绪队列</span>。就绪队列一般没有优先级时按先来先服务（FIFO）排队。

## 2.3 进程控制

进程控制是进程管理中最基本的功能，<span style="color:#e03131">一般由 OS 内核中的原语（Primitive）来实现</span>。原语是由若干条指令组成的、执行过程中不允许被中断的操作，也就是“原子操作”。

进程控制包括四类：进程创建、进程终止、进程阻塞与唤醒、进程挂起与激活。

### 2.3.1 进程的创建

**进程的层次结构：** 在 UNIX 中，进程 P 创建的进程叫子进程，子进程还可以再创建孙进程，形成一个家族。子进程可以继承父进程的资源，子进程撤销时要把资源还给父进程；父进程撤销时，要同时撤销它所有的子进程。<span style="color:#e03131">Windows 中不存在进程层次的概念</span>，所有进程地位相同，父进程通过“句柄”来控制子进程。

**进程图：** 描述进程家族关系的一棵有向树，结点是进程，有向边从父进程指向子进程。

**引起进程创建的事件：**

1. 用户登录：分时系统中用户登录成功，系统为该用户创建一个进程
2. 作业调度：批处理系统中作业调度程序选中某作业，为它创建进程
3. 提供服务：用户程序请求某种服务（如打印），系统创建一个提供该服务的进程
4. 应用请求：应用进程自己创建新进程（如 `fork()`），和自己并发完成任务

**进程创建过程（创建原语 Create）：**

1. <span style="color:#e03131">申请空白 PCB</span>，获得唯一的数字标识符
2. <span style="color:#e03131">为新进程分配运行所需的资源</span>，包括内存、文件、I/O 设备、CPU 时间等
3. <span style="color:#e03131">初始化 PCB</span>：标识信息、处理机状态信息、处理机控制信息（状态一般设为就绪或静止就绪）
4. <span style="color:#e03131">把新进程插入就绪队列</span>（如果就绪队列能接纳）

### 2.3.2 进程的终止

引起进程终止的事件：

- **正常结束**：进程任务完成，比如执行到 `exit` 或 Halt 指令
- **异常结束**：越界错、保护错、非法指令、特权指令错、运行超时、等待超时、算术运算错、I/O 故障等
- **外界干预**：操作员或 OS 干预、父进程请求、父进程终止

**进程终止过程：**

1. 根据被终止进程的标识符，从 PCB 集合中检索出该进程的 PCB，读出它的状态
2. 如果它正处于执行状态，立即终止它的执行，并<span style="color:#e03131">把调度标志设为真</span>，表示终止后要重新调度
3. 如果它还有子孙进程，<span style="color:#e03131">把所有子孙进程也终止</span>，防止它们成为不可控的进程
4. 把它拥有的全部资源归还给父进程或系统
5. 把它的 PCB 从所在队列（或链表）中移出，等其他程序来收集信息

### 2.3.3 进程的阻塞与唤醒

引起进程阻塞和唤醒的事件：

1. 向系统请求共享资源失败
2. 等待某种操作的完成（如等待 I/O 完成）
3. 新数据尚未到达（如合作进程还没把数据送来）
4. 等待新任务的到达（如网络服务进程没有新请求要处理）

**阻塞原语 `block()`：** <span style="color:#e03131">进程的阻塞是进程自身的一种主动行为。</span>具体过程是：立即停止执行 → 把 PCB 中的状态由执行改为阻塞 → 把 PCB 插入相应事件的阻塞队列 → 转调度程序重新调度，并保存被阻塞进程的 CPU 现场。

**唤醒原语 `wakeup()`：** 当被阻塞进程所期待的事件发生时，由**有关进程**（比如释放资源的进程、完成 I/O 的进程）调用唤醒原语。具体过程是：把被阻塞进程从阻塞队列中移出 → 把 PCB 中的状态由阻塞改为就绪 → 把 PCB 插入就绪队列。

<span style="color:#e03131">`block()` 和 `wakeup()` 必须成对使用</span>：一个进程在某处调用了阻塞原语，就必须在与之合作的另一个进程中（或其他相关进程中）安排唤醒原语，否则被阻塞的进程会永远阻塞下去。

### 2.3.4 进程的挂起与激活

**挂起原语 `suspend()`：** 先检查被挂起进程的状态，<span style="color:#e03131">活动就绪改为静止就绪，活动阻塞改为静止阻塞</span>。为了方便用户或父进程考查该进程的运行情况，把它的 PCB 复制到某指定内存区域。如果被挂起的进程正在执行，就转向调度程序重新调度。

**激活原语 `active()`：** 先把进程从外存调入内存，检查它的状态，<span style="color:#e03131">静止就绪改为活动就绪，静止阻塞改为活动阻塞</span>。如果系统采用抢占式调度，每当有静止就绪进程被激活插入就绪队列时，就要检查是否需要重新调度：比较它和当前执行进程的优先级，如果它更高，就立即剥夺当前进程的 CPU，让刚激活的进程运行。

## 2.4 进程通信

<span style="color:#e03131">进程通信是指进程之间的信息交换。</span>

- **低级进程通信**：进程的同步和互斥（如信号量机制）。缺点是效率低，每次只能交换很少的信息；通信对用户不透明，共享数据结构、同步和互斥都要程序员自己实现。
- **高级进程通信**：OS 提供的一组通信命令。优点是使用方便（通信过程对用户透明），能高效地传送大量数据。

### 2.4.1 进程通信的类型

高级通信机制分四类：

**1. 共享存储器系统（Shared-Memory System）**

- **基于共享数据结构的通信方式**：进程之间共用某些数据结构（如生产者-消费者问题中的有界缓冲区）。OS 只提供共享存储器，由程序员负责数据结构的设置和同步处理。<span style="color:#e03131">效率低，属于低级通信</span>。
- **基于共享存储区的通信方式**：在内存中划出一块共享存储区，进程通信前先向系统申请其中的一个分区，读写完再归还。<span style="color:#e03131">数据的形式和位置甚至访问控制都由进程自己负责，属于高级通信</span>。

**2. 管道通信系统（Pipe）**

<span style="color:#e03131">管道是用于连接一个读进程和一个写进程以实现它们之间通信的一个共享文件，又名 pipe 文件。</span>写进程以字符流形式把大量数据送入管道，读进程从管道里接收数据。

管道机制必须提供三方面的协调能力：

1. **互斥**：一个进程正在读写管道时，其他进程必须等待
2. **同步**：写进程写完一定量数据后睡眠等待，直到读进程取走数据再唤醒；读进程读空管道时睡眠等待，直到写进程写入数据再唤醒
3. **确定对方是否存在**：只有确定对方已存在时才能通信

**3. 消息传递系统（Message Passing System）**

进程不借助任何共享存储区或数据结构，而是以<span style="color:#e03131">格式化的消息（message）</span>为单位，把通信的数据封装在消息中，利用 OS 提供的一组通信命令（原语）在进程间传递。这是目前应用最广泛的通信机制，比如计算机网络中的报文。

- 直接通信方式：发送进程直接把消息发给接收进程
- 间接通信方式：通过共享中间实体（信箱）来发送和接收消息

**4. 客户机-服务器系统（Client-Server System）**

- **套接字（Socket）**：一个套接字就是一个通信标识类型的数据结构，是通信的端点。分为基于文件型（同一台机器上的进程通信）和基于网络型（不同主机上的进程通信）。
- **远程过程调用（RPC）和远程方法调用（RMI）**：让一台主机上的进程调用另一台主机上的进程，对程序员来说就像调用本地过程一样。如果涉及的软件是面向对象的，就叫远程方法调用，比如 Java 的 RMI。

### 2.4.2 消息传递通信的实现方式

**1. 直接消息传递系统**

发送进程利用 OS 提供的发送原语，直接把消息发送给目标进程。

- 对称寻址方式：发送和接收双方都要明确提供对方的标识符
  - 发送原语：`send(receiver, message)`
  - 接收原语：`receive(sender, message)`
- 非对称寻址方式：接收进程不用写发送方，改为 `receive(id, message)`，id 由系统填入发送进程的标识符。适合服务器这种不知道谁会来请求的情况。

**2. 信箱通信（间接通信方式）**

进程之间通过共享的中间实体<span style="color:#e03131">信箱（mailbox）</span>来通信。发送进程把消息投入信箱，接收进程从信箱里取走消息。信箱可以暂存消息，所以双方不用同时在线。

- 信箱结构：信箱头（信箱标识符、拥有者、口令、格子数等） + 信箱体（若干个可以存放消息的格子）
- 发送原语：`send(mailbox, message)`
- 接收原语：`receive(mailbox, message)`
- 信箱类型：
  - **私用邮箱**：用户进程自己建立，只有拥有者能读，其他进程只能往里发消息，拥有者结束时邮箱随之消失
  - **公用邮箱**：由 OS 创建，所有核准进程都能发送和读取，在系统运行期间始终存在
  - **共享邮箱**：由某进程创建，创建时指明可共享，并指出共享进程的名字，拥有者和共享者都能读取消息

### 2.4.3 实例：Linux 进程通信

Linux 支持的进程通信方式有六种：<span style="color:#e03131">管道、信号、消息队列、共享内存、信号量、套接字</span>。

| 方式 | 一句话说明 |
| --- | --- |
| 管道（pipe/FIFO） | 无名管道用于有亲缘关系的进程，有名管道（FIFO）有文件名，无关进程也能用 |
| 信号（signal） | 通知某进程发生了某个事件，比如 `kill -9` 就是给进程发 SIGKILL 信号 |
| 消息队列 | 内核中的消息链表，进程按消息类型收发 |
| 共享内存 | 多个进程映射同一块内存，是<span style="color:#e03131">最快的</span>通信方式，但要自己做同步 |
| 信号量 | 计数器，主要用来做进程之间的同步和互斥 |
| 套接字（socket） | 可以跨主机通信，网络编程都用它 |

**无名管道实例：** 父进程创建管道后 `fork()` 出子进程，子进程往管道里写 "test data"，父进程从管道里读出来。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define INPUT 0   /* 读端 */
#define OUTPUT 1  /* 写端 */

int main() {
    int file_descriptors[2];
    pid_t pid;                         /* 子进程号 */
    char buf[256];
    int returned_count;

    pipe(file_descriptors);            /* 创建无名管道 */
    if ((pid = fork()) == -1) {        /* 创建子进程 */
        printf("Error in fork\n");
        exit(1);
    }
    if (pid == 0) {                    /* 子进程 */
        printf("in the spawned (child) process...\n");
        close(file_descriptors[INPUT]);           /* 子进程写，关掉读端 */
        write(file_descriptors[OUTPUT], "test data", strlen("test data"));
        exit(0);
    } else {                           /* 父进程 */
        printf("in the spawning (parent) process...\n");
        close(file_descriptors[OUTPUT]);          /* 父进程读，关掉写端 */
        returned_count = read(file_descriptors[INPUT], buf, sizeof(buf));
        printf("%d bytes of data received from spawned process: %s\n",
               returned_count, buf);
    }
    return 0;
}
```

![无名管道：fork 之后子进程写、父进程读](/assets/img/os/ch2-pipe.svg)

**图解：** 中间的圆角框是管道，它本质上是内核里的一块缓冲区，左边是读端 `fd[0]`，右边是写端 `fd[1]`。

- `pipe()` 之后再 `fork()`，父子进程都拿着读端和写端两个文件描述符。
- 右上的子进程负责写，所以先 `close(fd[0])` 关掉自己不用的读端，再 `write(fd[1], ...)` 把 "test data" 写进管道（橙色箭头）。
- 左上的父进程负责读，所以先 `close(fd[1])` 关掉写端，再 `read(fd[0], ...)` 从管道里取数据（蓝色箭头）。
- 管道里的红色箭头表示<span style="color:#e03131">数据是单向流动的</span>：从写端流向读端。想双向通信就要建两个管道。

**有名管道实例：** 有名管道（FIFO）在文件系统里有一个名字（这里叫 `mypipe`，可以用 `mkfifo mypipe` 创建），所以没有亲缘关系的进程也能通过这个名字打开它。下面的程序先从 `mypipe` 读数据，再往里写数据：

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    FILE *in_file, *out_file;
    int count = 1;
    char buf[80];

    in_file = fopen("mypipe", "r");             /* 读有名管道 */
    if (in_file == NULL) {
        printf("Error in fopen.\n");
        exit(1);
    }
    while ((count = fread(buf, 1, 80, in_file)) > 0)
        printf("received from pipe: %s\n", buf);
    fclose(in_file);

    out_file = fopen("mypipe", "w");            /* 写有名管道 */
    if (out_file == NULL) {
        printf("Error in fopen.\n");
        exit(1);
    }
    sprintf(buf, "this is test data for the named pipe example.\n");
    fwrite(buf, 1, 80, out_file);
    fclose(out_file);
    return 0;
}
```

## 2.5 线程的概念

### 2.5.1 线程的引入

| 时间 | 事件 |
| --- | --- |
| 20 世纪 60 年代中期 | 提出进程概念 |
| 20 世纪 80 年代中期 | 提出线程概念 |
| 20 世纪 90 年代以后 | 多处理机系统广泛引入线程 |

- <span style="color:#e03131">引入进程的目的</span>：使多个程序能并发执行，提高资源利用率和系统吞吐量。
- 进程有两个基本属性：<span style="color:#e03131">进程是一个可拥有资源的独立单位；进程是一个可独立调度和分派的基本单位。</span>
- 问题在于进程“太重”：创建、撤销、切换进程时，系统都要分配或回收资源、保存和恢复现场，时空开销很大，限制了并发程度的进一步提高。
- <span style="color:#e03131">引入线程的目的</span>：把进程的两个属性分开，<span style="color:#e03131">进程作为拥有资源的基本单位（重型进程），线程作为调度和分派的基本单位（轻型进程）</span>。这样可以减少程序并发执行时付出的时空开销，使 OS 具有更好的并发性，也更适用于对称多处理机（SMP）系统。

### 2.5.2 线程与进程的比较

| 比较项 | 进程 | 线程 |
| --- | --- | --- |
| <span style="color:#e03131">调度的基本单位</span> | 传统 OS 中进程既是资源拥有单位又是调度单位 | 引入线程的 OS 中，线程是调度和分派的基本单位；同一进程内的线程切换不会引起进程切换，切到另一个进程的线程才会引起进程切换 |
| 并发性 | 进程之间可以并发 | 不仅进程之间可以并发，一个进程中的多个线程之间也可以并发 |
| <span style="color:#e03131">拥有资源</span> | 进程是拥有资源的基本单位 | 线程本身基本不拥有系统资源，只有一点保证独立运行的资源（TCB、程序计数器、寄存器、栈），允许多个线程共享所属进程的资源 |
| 独立性 | 不同进程之间独立性高，地址空间和资源互相隔离 | 同一进程中不同线程之间的独立性低得多，共享地址空间和资源 |
| <span style="color:#e03131">系统开销</span> | 创建、撤销、切换进程的开销大 | 创建、撤销、切换线程的开销远小于进程；同一进程中线程间的同步和通信也更简单 |
| 支持多处理机 | 单线程进程只能在一个 CPU 上运行 | 一个进程的多个线程可以分配到多个 CPU 上并行执行 |

![单线程进程与多线程进程](/assets/img/os/ch2-process-thread.svg)

**图解：** 左边是传统的单线程进程，右边是有三个线程的进程。

- 上面的蓝色区域是进程拥有的资源：代码段、数据段、打开的文件。在多线程进程里，<span style="color:#e03131">这些资源由所有线程共享</span>。
- 下面每个黄色小框是一个线程，每个线程都有自己的寄存器（包括程序计数器）、栈和线程控制块 TCB。这些是线程独立运行必需的最少资源。
- 所以线程切换只需要换寄存器和栈，不用换整个地址空间，开销比进程切换小得多。

### 2.5.3 线程状态和线程控制块

**线程的三种状态：** <span style="color:#e03131">执行态、就绪态、阻塞态</span>，状态转换和进程的状态转换一样。

**线程控制块 TCB（Thread Control Block）：** 每个线程都有一个 TCB，记录用于控制和管理线程的信息，包括：

- 线程标识符
- 一组寄存器（程序计数器 PC、状态寄存器、通用寄存器）
- 线程运行状态
- 优先级
- 线程专有存储区（切换时保存现场）
- 信号屏蔽
- 堆栈指针

**多线程 OS 中的进程属性：** 进程是一个可拥有资源的基本单位；多个线程可在一个进程内并发执行；<span style="color:#e03131">进程已不是可执行的实体</span>，所谓“进程处于执行状态”，实际上是指该进程中的某个线程正在执行。

## 2.6 线程的实现

### 2.6.1 线程的实现方式

线程有三种实现方式：<span style="color:#e03131">内核支持线程（KST）、用户级线程（ULT）、两者的组合方式</span>。

**1. 内核支持线程 KST（Kernel Supported Threads）**

在内核空间实现，线程的创建、阻塞、撤销和切换都由内核完成，内核为每个线程设置一个 TCB，并据此感知线程的存在。

| 优点 | 缺点 |
| --- | --- |
| 在多处理机系统中，内核可以同时调度同一进程中的多个线程并行执行 | <span style="color:#e03131">对用户线程的切换开销较大</span>：同一进程内的线程切换也要从用户态转到内核态 |
| 一个线程被阻塞了，内核可以调度该进程中的其他线程或其他进程的线程 | |
| 内核支持线程的数据结构和栈很小，切换比较快、开销小 | |
| 内核本身也可以采用多线程技术，提高执行速度和效率 | |

**2. 用户级线程 ULT（User Level Threads）**

在用户空间实现，线程的创建、撤销、同步和通信都不需要内核参与，<span style="color:#e03131">内核完全不知道用户级线程的存在</span>，调度仍然以进程为单位。

| 优点 | 缺点 |
| --- | --- |
| 线程切换不需要转换到内核空间，节省了模式切换开销 | <span style="color:#e03131">系统调用的阻塞问题</span>：一个线程执行系统调用被阻塞时，整个进程中的所有线程都会被阻塞 |
| 调度算法可以是进程专用的，不同进程可以按需选择不同的调度算法 | <span style="color:#e03131">不能利用多处理机</span>：内核每次只给一个进程分配一个 CPU，进程中只有一个线程能执行 |
| 线程的实现与 OS 平台无关，所有应用程序都可以共享线程管理代码 | |

**3. ULT 与 KST 的组合方式**

内核支持多个内核支持线程的建立、调度和管理，同时也允许用户应用程序建立、调度和管理用户级线程。根据用户级线程和内核支持线程连接方式的不同，有三种模型：

![用户级线程与内核线程的三种组合模型](/assets/img/os/ch2-thread-models.svg)

**图解：** 每个面板上方的黄色区域是用户空间，里面的 U 是用户级线程；下方的蓝色区域是内核空间，里面的 K 是内核控制线程；连线表示某个用户级线程映射到哪个内核线程上运行。

- **多对一模型**：4 个 U 全部连到 1 个 K。线程管理在用户态完成，效率高；但<span style="color:#e03131">一个线程的阻塞系统调用会导致整个进程阻塞</span>，多个线程也不能并行运行在多个处理器上。用于不支持内核线程的系统，例如 Solaris Green Threads、GNU Portable Threads。
- **一对一模型**：每个 U 都有自己的 K。并发性比多对一好，<span style="color:#e03131">允许多个线程并行运行在多个处理器上</span>；缺点是每创建一个用户线程就要创建一个对应的内核线程，开销较大，所以要限制线程数量。例如 Windows NT/XP/2000、Linux、Solaris 9 及以后版本、OS/2。
- **多对多模型**：4 个 U 映射到 2 个 K，<span style="color:#e03131">内核线程数小于或等于用户线程数</span>。OS 可以创建足够多的内核线程，结合了前两种模型的优点。例如 Solaris 9 以前的版本、带 ThreadFiber 开发包的 Windows NT/2000。

### 2.6.2 线程的具体实现

**1. 内核支持线程的实现**

系统在创建一个新进程时，为它分配一个<span style="color:#e03131">任务数据区 PTDA（Per Task Data Area）</span>，其中包括若干个线程控制块 TCB 的空间。每当进程要创建一个线程时，就为新线程分配一个 TCB，填入有关信息，并分配必要的资源。内核支持线程的创建、撤销都和进程类似，调度和切换也和进程很相似，但开销更小。

**2. 用户级线程的实现**

用户级线程在用户空间实现，所有用户级线程都有相同的结构，都运行在一个中间系统上。中间系统有两种实现方式：

- <span style="color:#e03131">运行时系统（Runtime System）</span>：用于管理和控制线程的函数（过程）的集合，包括创建和撤销线程的函数、线程同步和通信的函数、实现线程调度的函数等。用户级线程不能直接使用系统调用，需要通过运行时系统间接使用内核服务。
- <span style="color:#e03131">内核控制线程</span>：又称轻型进程 LWP（Light Weight Process）。每个进程可以有多个 LWP，每个 LWP 都有自己的 TCB。用户级线程通过连接到一个 LWP 上来获得内核服务，LWP 就像用户级线程和内核之间的“桥梁”。

### 2.6.3 线程的创建与终止

**线程的创建：** 应用程序启动时，通常只有一个线程在执行，叫<span style="color:#e03131">初始化线程</span>，它的主要作用是创建新线程。创建新线程时，利用线程创建函数（或系统调用），提供相应的参数（如指向线程主程序的入口指针、堆栈大小、调度优先级等），函数执行完后返回一个线程标识符供以后使用。

**线程的终止：** 线程完成任务后自愿退出，或运行中出现错误、被强行终止时，由终止线程调用相应的函数（或系统调用）执行终止操作。有些线程（主要是系统线程）一旦建立就一直运行下去，不会被终止。<span style="color:#e03131">线程终止后并不立即释放它占有的资源</span>，只有当进程中的其他线程执行了分离函数后，被终止的线程才与资源分离，资源才能被其他线程利用。被终止但还没释放资源的线程，仍可以被需要它的线程调用（join），使它重新恢复运行。

## 本章思考题

**1. 系统中有 N 个进程（单处理机），某一时刻运行、就绪、等待（阻塞）的进程最多和最少各几个？**

| 状态 | 最多 | 最少 |
| --- | --- | --- |
| 运行 | 1 | 0 |
| 就绪 | N − 1 | 0 |
| 等待 | N | 0 |

运行进程最少为 0，是因为可能所有进程都在等待（比如都在等 I/O），这时 CPU 空闲。就绪进程最多 N − 1，因为只要有就绪进程，CPU 就会被分给其中一个。

**2. 有没有“等待 → 运行”和“就绪 → 等待”这样的状态转换？**

都没有。等待（阻塞）的进程在事件发生后只能先变成就绪，再由调度程序选中才能运行；就绪进程没有在运行，不可能发起 I/O 请求等事件让自己阻塞。

**3. 一个状态转换的发生，是否一定导致另一个转换发生？**

不一定。可能的情况有：

- 运行 → 阻塞：会引起某个就绪进程变成运行（如果就绪队列不空）
- 运行 → 就绪（时间片完）：会引起某个就绪进程变成运行（可能就是它自己）
- 阻塞 → 就绪：如果采用抢占式调度且被唤醒的进程优先级更高，可能引起当前运行进程变成就绪；非抢占式下不会引起其他转换
- 就绪 → 运行：不会引起其他转换，它本身就是被别的转换引发的

**4. 举 3 个日常生活中类似进程的例子**

- 厨师照着菜谱做菜：菜谱是程序（静态的），“正在做这道菜”的过程是进程（动态的），等水烧开就是阻塞
- 医院看病：挂号排队是就绪，正在看诊是执行，被叫去做检查等结果是阻塞，结果出来后回到排队是被唤醒
- 一个人同时煮饭、洗衣服、回消息：看起来同时进行，其实是在几件事之间来回切换，就像单 CPU 上多个进程并发
